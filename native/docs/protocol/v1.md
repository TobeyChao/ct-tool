# ct worker 协议 v1

本文件是协议语义的唯一权威定义。三份材料同源维护，由
`native/tests/protocol` 的契约测试保证一致：

| 材料 | 位置 | 作用 |
|---|---|---|
| 语义文档 | 本文件 | 行为规则、方法语义、错误模型 |
| 机器类型 | `native/crates/ct-protocol` | Rust 类型（serde 注解即线格式） |
| 机器 schema + 样例 | `docs/protocol/schema/protocol.v1.json`、`docs/protocol/examples/*.ndjson` | Dart 生成/校验与 golden 对照 |

任何协议变更必须同时更新三者；不兼容变更递增 `PROTOCOL_VERSION`。

## 1. 传输

- UTF-8 NDJSON over stdin/stdout：每行一条完整 JSON 消息，行内不得含裸换行。
- stderr 仅用于诊断，永不承载协议消息；JSON 模式下 stdout 无日志混入。
- 单条消息上限 4 MiB（`MAX_MESSAGE_BYTES`，按消息体计、不含行尾换行）；超限回 `message-too-large`
  并整行丢弃，连接保持可用（客户端不必重连）。
- worker 是应用私有子进程：不开端口，不需要 TLS/认证。

## 2. 握手

连接建立后客户端发送第一条消息 `hello`（含 `protocolVersion`、`coreVersion`、
`capabilities`）；worker 回复自己的 `hello`，或回 `protocol-mismatch` 错误后关闭。

- 双方 `protocolVersion` 主版本必须一致，否则握手失败，业务请求不得执行。
- 客户端按 worker `capabilities` 启用入口；缺失能力的入口显式禁用，
  不得静默降级或回退到其他实现。
- hello 之前收到任何其他消息，回 `malformed-message` 并关闭连接。

## 3. workspaceId

worker 在 `workspace.open` 时计算并绑定 `workspaceId`：

1. `workspaceRoot` 规范化：解析为绝对路径、解析符号链接、Unicode NFC；
2. 大小写按目标文件系统规则折叠（Windows/macOS 默认大小写不敏感）；
3. 结果对客户端**不透明**：客户端只做字符串等值比较，不解析其内容。

同一连接内所有事件/响应携带该值；客户端切换工作区后，携带旧
`workspaceId` 的迟到事件仍归属原任务，不得更新当前视图。

## 4. 请求 / 响应 / 事件

请求：`{type:"request", requestId, method, workspaceRoot, params}`。

- `requestId`：连接内单调分配、不得重复；重复收到已接受的 ID 时
  拒绝执行（`duplicate-request-id`），写请求不会被执行两次。
- `seq`：worker 发出的每条事件/响应携带连接内单调递增序号。
- 终态：每个**已接受**的请求至多一个终态（`result` 或 `error`）。
  任务取消以 `result.payload.outcome = "cancelled"` 表示，不是 error。
- 事件：`progress`（可合并，同一请求只保留最新一条）、`log`（可限流丢弃）、`issue`（不可丢弃）。
  队列有界：可丢弃事件在队列满时直接丢弃，`issue` 与终态阻塞直到送达，
  因此事件流既不会阻塞终态也不会挤掉终态。
- 写任务因业务校验失败终结时，`error.issues[]` 的每条明细在终态之前以 `issue` 事件同步送出，
  数量与终态明细一一对应；只消费终态的客户端可以忽略这些事件。

无法解析出 `requestId` 的入站消息（非法 JSON、超限、hello 之前的业务消息）
产生无 `requestId`/`workspaceId`/`seq` 的 `error` 消息。

## 5. 方法清单

| 方法 | 写操作 | 说明 |
|---|---|---|
| `workspace.open` | 否 | 打开并绑定工作区；有待恢复事务时返回 `recovery_needed` 状态 |
| `workspace.snapshot` | 否 | 只读快照；待恢复时报 `recovery-needed`，不返回半套资源 |
| `workspace.status` | 否 | 概览；不写缓存、不做恢复 |
| `workspace.recover` | 是 | 显式恢复（持写锁）；返回新基线，不重放任何旧请求 |
| `resources.list` | 否 | 资源清单（名称/类别/来源路径/excel_file/json_key，Table 另带 `indexes`：已声明的索引 kind）+ `schemaRevision`：编辑草稿的基线，客户端据此构造 candidate/save 守卫 |
| `table.preview` | 否 | 分页只读预览；单元格整数适用大整数规则。列另带字段属性（`i18n`/`serverOnly`/`comment`/`ref`/`excelColumns`，未声明即缺席），编辑器据此原样回显 |
| `schema.candidate` | 否 | 基线+commands+cursor → 候选、净差异、candidateHash；回显 draftGeneration。撤销只移动 cursor、不裁剪 commands，生效前缀由内核解释 |
| `schema.save` | 是 | 双守卫（schemaRevision + candidateHash）；仅写 YAML |
| `template.plan` | 否 | 模板迁移预检 |
| `template.generate` | 是 | 显式生成/迁移；失败不覆盖原工作簿 |
| `validate` | 否 | 完整校验覆盖；不写持久缓存 |
| `export` | 是 | 本地发布并记账；桌面不自动部署 |
| `deploy` | 是 | 独立部署；不更新成功账本 |
| `i18n.query/save` | 否/是 | 分页查询；单条保存遵守 text/confirmed/status 规则 |
| `i18n.sync/status/compact` | 是/否/是 | compact 支持 dryRun |
| `history.list` | 否 | 最近五次成功桌面导出 |
| `logs.list` | 否 | 模块/级别筛选，分页 |
| `tasks.list` / `tasks.issues` / `tasks.dismiss` | 否/否/是 | 任务查询、问题分页、关闭通知（重连不复活） |
| `cancel` | 控制 | 见 §6 |
| `shutdown` | 控制 | 见 §6 |

## 6. 取消与关闭

- `cancel` 是普通方法，参数 `{targetRequestId}`；结果为
  `cancelling` / `already_terminal` / `unknown_request`。
- 取消仅设置协作式 token：发布边界前在步间/表间生效；进入发布阶段后
  延迟到事务完成，客户端展示「正在完成」，以内核终态为准。
- 写任务执行期间 worker 必须继续读取控制消息（业务在工作线程执行）。
- `shutdown` 返回终态后：新的业务请求一律 `busy`；已接受的写任务照常跑到发布边界并送达终态；
  worker 继续读取输入直到客户端关闭 stdin（EOF）后退出。因此**客户端必须在收到 shutdown
  终态后关闭输入管道**（或终止子进程）；正常退出不得用强杀代替取消。

## 7. 断连语义

stdin EOF 视为隐式 shutdown：

- 已接受的写任务继续执行到最近的**发布安全边界**（完整提交或完整回滚），
  随后 worker 退出；读任务可直接中止。
- 断连后无法送达终态，客户端必须把该任务标记为 `unknown`：
  不谎报成功或取消，不自动重放写请求；重连后通过
  `workspace.status` / `workspace.recover` 收敛状态。

## 8. 错误模型

`error` 消息的 `error.code` 是稳定机器码：

| code | 含义 |
|---|---|
| `protocol-mismatch` | 握手失败 |
| `malformed-message` | 非法 JSON / 信封缺字段 |
| `message-too-large` | 超过 4 MiB |
| `unknown-method` | 未实现的方法名 |
| `duplicate-request-id` | 连接内 requestId 重复 |
| `stale-page` | 分页令牌绑定的快照已过期 |
| `busy` | 同工作区写任务冲突 |
| `recovery-needed` | 存在待恢复事务 |
| `internal` | 未分类内部错误（message 供诊断） |

业务失败使用 `error` 终态 + `error.issues[]` 明细（`code/resource/fieldPath/
excelRow/file`），客户端据此定位，不解析人类可读日志。`excelRow` 是
原始 Excel 行号，非 Excel 来源的问题缺省；无明细时 `issues` 键省略。

任务类方法（export/template.generate/schema.save/i18n.sync/compact/deploy/
workspace.recover/tasks.dismiss）在**工作线程**执行：主循环继续读取
`cancel`/`shutdown`；事件顺序为若干 progress/log/issue + 恰好一个终态。
只读方法在主循环内同步执行，不产生事件。

## 9. 分页

- 参数 `{cursor?, limit?}`；响应 `{items|entries|rows, revision, nextCursor?}`——所有分页响应都在
  同层回传 `revision`（`table.preview`/`i18n.query`/`logs.list`/`tasks.issues`）。
- `revision` 在任何写任务成功或检测到工作区被外部修改时推进；重复打开同一工作区不推进。
- `cursor`/`nextCursor` 为不透明 token，绑定产生它的快照 `revision`。
- 携带过期令牌的请求返回 `stale-page`，客户端整页重查；
  不得混合两个 revision 的行数据。

## 10. 大整数

payload **任意深度**上，绝对值超出 ±(2^53-1) 的整数编码为
`{"$int": "<decimal>"}`；范围内保持 JSON number。`$int` 是保留键，
业务数据不得使用。解码端把合法标签对象还原为精确整数；非法标签
（多键、非字符串、非十进制）原样保留并按业务校验报错。

该规则只影响传输表示，不改变游戏产物 JSON 的格式。

## 11. Schema 候选与保存

- `schema.candidate` 参数：`schemaRevision`（草稿基线：**字符串**，
  schema 源文件集合的 sha256 十六进制摘要；计数器无法检测工作区被外部
  修改，故不使用整数）、`commands`（`{kind, payload}`，kind 词表由内核
  拥有并校验：`add_resource`/`delete_resource`/`rename_resource`/
  `rename_field`/`add_field`/`delete_field`/`move_field`/`set_property`/
  `set_type`/`set_enum_values`/`rename_enum_item`/`set_indexes`）、
  `cursor`（不透明撤销游标：命令序号的十进制字符串）、
  `draftGeneration`（客户端单调递增）。
- 参数键名以内核为准：`set_type` 用 `type_text`（snake_case）；
  `set_indexes` 的 `table` 必须是资源 id（`table:Item`，候选按 resource_id 合并索引）；
  `rename_enum_item` 用 `oldName`/`newName`/`originalOrdinal`；
  `set_property` 的属性名白名单是 `comment`/`i18n`/`server_only`/`excel_columns`/`ref`。
- 响应回显 `draftGeneration`；客户端丢弃与当前代次不匹配的迟到响应。
- 刷新候选不得推进草稿基线；保存成功才替换基线。
- `schema.save` 必须同时携带 `schemaRevision` + `candidateHash`；
  任一失配拒绝且不写任何文件。保存仅写 YAML，不动 Excel、翻译、
  产物或成功账本。

## 12. 桌面状态：历史、日志与任务通知

- `history.list` 读自**配置的 `cache_dir`** 下 `history.json`（格式 `desktop-history/1`），
  最新在前、最多 5 条，跨 worker 重启保留；只有桌面导出（`record_history`）会追加，
  CLI 导出永不写该文件。条目状态是稳定码（当前仅 `success`），文本由客户端本地化。
- **历史写失败不得推翻已成功的业务提交**：导出终态仍是 `result` +
  `payload.outcome = "succeeded"`，同时以一条 `log` 事件与
  `payload.issues[]`（`code: "history-write-failed"`）分开报告，客户端不得据此重放导出。
- `logs.list` 是**连接内**环形缓冲（上限 2000 条，按模块/级别筛选后分页）；握手、
  取消等控制消息记在 `control` 模块下。跨连接不保留。
- `tasks.*` 同样按连接归属：`tasks.dismiss` 只关闭本连接的通知；重连后任务列表为空，
  已关闭的通知因此不会复活。写任务失败的问题明细可通过 `tasks.issues` 分页取回，
  与终态 `error.issues[]` 逐条一致（含 `excelRow` 原始行号）。

## 13. 样例目录

`docs/protocol/examples/` 每个文件是一段完整消息序列（每行一条）：

- `hello.ndjson` / `hello_mismatch.ndjson`：握手成功与不兼容
- `workspace_open.ndjson`：打开工作区
- `schema_candidate.ndjson` / `schema_save.ndjson`：候选与保存
- `export_progress.ndjson`：进度/日志/终态
- `export_cancel.ndjson`：取消流
- `preview_bigint.ndjson`：大整数标签
- `pagination_stale.ndjson`：快照过期
- `duplicate_request_id.ndjson`：重复请求 ID
- `malformed.ndjson`：连接级错误（非法行本身无法入样，见 §4）
- `shutdown.ndjson`：安全关闭

`native/fixtures/protocol/wire-cases.json` 是**同源契约夹具**：Rust 侧
（`tests/protocol/tests/contract_cases.rs`）用真实 worker 逐例执行并按占位符核对，
Dart 侧（`launcher/test/protocol/wire_cases_test.dart`）解码同一批消息并核对消息类型、
错误码词表与大整数精度。占位符 `<n> <id> <message> <sha256> <any>`、引用
`{"$from": "<requestId>.<字段>"}`、外部改动 `change` 与重连 `conn` 的语义见夹具自身的
`placeholders`/`rules` 段。

golden samples 是 Dart/Rust 双方的契约夹具：改动必须同时通过
`tests/protocol` 的 Rust 类型往返测试与 JSON Schema 校验。
