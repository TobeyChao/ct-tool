# Flutter macOS 侧栏与窗口交通灯的布局研究

研究日期：2026-09-22。以下将 Apple 和 Flutter 官方行为、插件作者提供的方案与本项目的设计判断分开；尺寸建议是待真机验证的工程取值，并非 Apple 规定的像素数。

## 官方原则

- Apple 将显示/隐藏侧栏的控制归入工具栏**最前端**，在返回按钮旁、标题之前；macOS 的工具栏位于窗口顶部边框内，可位于标题栏下方或与其合并。侧栏也可通过“显示”菜单中的显示/隐藏命令操作；侧栏默认应易于发现，缩窄窗口时可自动隐藏。[Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars#Item-groupings) · [Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars#Best-practices) · [Apple Sidebars — macOS](https://developer.apple.com/design/human-interface-guidelines/sidebars#macOS)
- 系统窗口按钮始终占有自己的实际可视和命中区域；`NSWindow.standardWindowButton(_:)` 能取得窗口层级中标准按钮。工具栏也要在窄窗口为控件设计溢出布局，侧栏切换这种关键控件应保持可达。[NSWindow.standardWindowButton](https://developer.apple.com/documentation/appkit/nswindow/standardwindowbutton(_:)) · [Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars#Best-practices)

## 三种标题栏场景

| 场景 | 系统与内容边界 | 切换按钮、空白与拖动 |
| --- | --- | --- |
| **原生标题栏/工具栏** | Flutter 内容位于 AppKit 分配的内容区；系统管理交通灯。`NSWindow.toolbarStyle` 决定工具栏相对标题栏的位置。[NSWindow.toolbarStyle](https://developer.apple.com/documentation/appkit/nswindow/toolbarstyle-swift.property) | 优先将切换按钮做成原生工具栏前端项目；也可在内容区首行放按钮，但它会在标题栏**下方**，不应假装占用交通灯所在行。[Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars#Item-groupings) |
| **透明标题栏** | `titlebarAppearsTransparent` 只让标题栏背景不绘制，以显示其下的内容；Apple 指出它与 `fullSizeContentView` 配用才有意义。透明不等于移除原生标题栏或交通灯。[NSWindow.titlebarAppearsTransparent](https://developer.apple.com/documentation/appkit/nswindow/titlebarappearstransparent) | 让侧栏背景延伸至顶端，但图标、文字及切换按钮须避开交通灯；可采用原生 `NSToolbar` 项目或 `NSTitlebarAccessoryViewController` 承载顶部控件，由 AppKit 安排其标题栏位置和进出全屏时的变化。[NSTitlebarAccessoryViewController](https://developer.apple.com/documentation/appkit/nstitlebaraccessoryviewcontroller) |
| **全尺寸内容覆盖标题栏区** | `.fullSizeContentView` 使 `contentView` 覆盖整窗，**仅在仍有标题栏的窗口生效**；`contentLayoutRect`/`contentLayoutGuide` 给出不被工具栏遮住的内容区。[NSWindow.StyleMask.fullSizeContentView](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/fullsizecontentview) · [NSWindow.contentLayoutRect](https://developer.apple.com/documentation/appkit/nswindow/contentlayoutrect) | 顶部可画背景、留专用窗口按钮避让带，再把侧栏切换放在避让带右侧或内容区顶行；空白背景可以拖窗，交互按钮及其命中框不能被拖动覆盖。Flutter 的 `SafeArea` 使用 `MediaQuery.padding`，须验证当前嵌入方式有没有把原生标题栏占位传给 Flutter，不能假定它自动替代交通灯的**横向**避让。[Flutter SafeArea & MediaQuery](https://docs.flutter.dev/ui/adaptive-responsive/safearea-mediaquery) · [NSView.safeAreaInsets](https://developer.apple.com/documentation/appkit/nsview/safeareainsets) · [NSWindow.isMovableByWindowBackground](https://developer.apple.com/documentation/appkit/nswindow/ismovablebywindowbackground) |

AppKit `NSView.safeAreaInsets` 表示未被标题栏或上层视图遮挡的区域，视图尚未装入可见层级时可能为零；读取时机和坐标系必须正确。它和 Flutter `MediaQuery.padding` 属不同层级的数据，**不能直接推断前者已映射到后者**。`NSTitlebarAccessoryViewController` 适合确实要把控件放入原生标题栏时使用，可设置 `layoutAttribute`，由窗口添加并在全屏切换时处理位置。[NSView.safeAreaInsets](https://developer.apple.com/documentation/appkit/nsview/safeareainsets) · [NSTitlebarAccessoryViewController](https://developer.apple.com/documentation/appkit/nstitlebaraccessoryviewcontroller) · [NSWindow.addTitlebarAccessoryViewController](https://developer.apple.com/documentation/appkit/nswindow/addtitlebaraccessoryviewcontroller(_:))

## 对本应用的建议

[window_options.dart](../../lib/services/window_options.dart) 在 macOS 使用 `TitleBarStyle.hidden` 且显示原生按钮。当前 [desktop_title_bar.dart](../../lib/ui/widgets/desktop_title_bar.dart) 为 macOS 绘制 40 px 顶栏、使用 18 px 品牌标志，维持 Flutter 顶栏控件原有的共同中心线；[main.dart](../../lib/main.dart) 通过 `macos_window_utils` 的 `addToolbar()` 与 `setToolbarStyle(.unifiedCompact)` 让 AppKit 自行排列红黄绿按钮，[app.dart](../../lib/app.dart) 预留 80 px 避让空间：开关固定在交通灯右侧，标题可跨过侧栏宽度，底线划分顶栏和内容区，侧栏分界纵线不延伸到顶栏。原生 [MainFlutterWindow.swift](../../macos/Runner/MainFlutterWindow.swift) 保留 AppKit 对三个窗口按钮的位置和悬停交互管理；此前手动内移 8 pt、下移 6 pt 导致按钮画面与悬停区域错位，已移除该定位约束。[Info.plist](../../macos/Runner/Info.plist) 显式声明 `NSHighResolutionCapable`，允许在高分辨率显示器上使用 Retina 渲染；提供的截图可能经过缩放，不能据此判断原生按钮是否真的以低分辨率绘制。插件自身示例支持 `TitleBarStyle.hidden`，具体效果仍须以目标 macOS 真机为准。[window_manager 作者文档](https://pub.dev/packages/window_manager#quick-start)

1. **近期最小方案**：保留原生红黄绿按钮与现有自绘顶栏，把同一个侧栏切换按钮放在交通灯避让带**右侧的顶栏固定位置**，展开和收起时都能在此操作；收起态即使按钮落在 56 px 图标栏边界右侧也不占用交通灯。若目标系统的标题栏命中层阻止顶栏按钮点击，则在图标栏下一行补一个恢复入口作为兼容方案。两种布局都应复用同一处状态与动作；macOS“显示”菜单命令可在后续原生菜单适配时提供。不要把当前 80 px 当跨 macOS 版本的标准值：实际按三个原生按钮的可见框、命中框和控件间距测量并留余量。[Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars#Item-groupings) · [Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars#Best-practices) · [NSWindow.standardWindowButton](https://developer.apple.com/documentation/appkit/nswindow/standardwindowbutton(_:))
2. **若要真正融入系统标题栏**：评估 `NSToolbar` 前端切换项；有特殊布局时再评估 `NSTitlebarAccessoryViewController`。若只是想让侧栏底色延伸到顶部，可用透明标题栏加全尺寸内容，交互仍按原生标题栏/安全布局单独处理。`macos_window_utils` 已在本项目接入，用于添加空工具栏和设置样式；它也提供透明标题栏、全尺寸内容及 `TitlebarSafeArea`，但这些能力仍由现有 `window_manager` 或 Flutter 布局负责。`macos_ui` 作者文档示例提供整套可切换侧栏，可作为未来外壳调整的参考。[Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars#Item-groupings) · [macos_window_utils 作者文档](https://pub.dev/packages/macos_window_utils#getting-started) · [macos_ui 作者文档](https://pub.dev/packages/macos_ui#macoswindow)
3. **缩放与全屏**：按窗口实际可用宽度决定侧栏折叠，不因折叠而丢失当前选中项；窄时优先保留主内容、切换入口与可拖动的空白顶栏。Flutter 建议用 `LayoutBuilder` 或 `MediaQuery.sizeOf` 判断可用尺寸；Apple 允许窗口缩窄时自动隐藏侧栏。进入全屏继续提供侧栏开关，不要假定交通灯始终常显或顶栏安全高度恒定，使用系统全屏行为并在进入/退出后核对布局。[Flutter adaptive best practices](https://docs.flutter.dev/ui/adaptive-responsive/best-practices#avoid-device-orientation-based-layouts) · [Apple Sidebars — macOS](https://developer.apple.com/design/human-interface-guidelines/sidebars#macOS) · [Apple Going full screen](https://developer.apple.com/design/human-interface-guidelines/going-full-screen#macOS)

**真机验收**：在目标 macOS 版本及缩放设置中测量交通灯的实际位置和点击框，逐一点击三按钮、切换侧栏、拖动空白标题栏，并检查窗口最小宽度、全屏进出及恢复；确认当前 `window_manager` 版本中 `TitleBarStyle.hidden` 如何设置 AppKit 样式、Flutter `MediaQuery.padding` 值和图标栏首项是否可见。[window_manager 作者 API](https://pub.dev/documentation/window_manager/latest/window_manager/WindowManager-class.html) · [Flutter SafeArea & MediaQuery](https://docs.flutter.dev/ui/adaptive-responsive/safearea-mediaquery)。插件项目有一条 [macOS Tahoe 顶部按钮显示但不可点击的用户报告](https://github.com/leanflutter/window_manager/issues/565)（关闭为 not planned）；这是需真机检验的兼容性风险，**尚无证据表明本项目复现**。

## 专题：窗口按钮、工作区标题与局部分隔线

### 一手 API 与 Apple 窗口示例的边界

- **交通灯的位置与控制权**：[`NSWindow.standardWindowButton(_:)`](https://developer.apple.com/documentation/appkit/nswindow/standardwindowbutton(_:)) 返回窗口视图层级里的原生按钮，可能为 `nil`；Apple 的 [WWDC20 AppKit 演示](https://developer.apple.com/videos/play/wwdc2020/10104/?time=353)通过统一工具栏及 inline title 安排顶部控件，未要求应用固定红黄绿坐标。[`windowTitlebarLayoutDirection`](https://developer.apple.com/documentation/appkit/nswindow/windowtitlebarlayoutdirection) 还指出标准按钮连同标题参与从右到左的标题栏布局。建议保留 AppKit 管理的原生按钮、测量其实际 frame 并避让。原生代码也能对获取的按钮调用通用 [`NSView.setFrameOrigin(_:)`](https://developer.apple.com/documentation/appkit/nsview/setframeorigin(_:)) 改 frame，但这是**可选的手动定制，并非 Apple 推荐的窗口按钮定位接口**；工具栏/全屏/布局方向/系统版本变化后位置可能需要重新校准，不能以一次修改作为稳定契约。插件也没有公开按钮坐标参数。[插件源码](https://github.com/leanflutter/window_manager/blob/main/packages/window_manager/macos/window_manager/Sources/window_manager/WindowManager.swift#L379-L402)
- **当前插件具体做什么**：已安装的 `window_manager` 0.5.2 在 [macOS Swift `setTitleBarStyle`](https://github.com/leanflutter/window_manager/blob/main/packages/window_manager/macos/window_manager/Sources/window_manager/WindowManager.swift#L379-L402) 中，`hidden` 设置 `titleVisibility = .hidden`、`titlebarAppearsTransparent = true`、插入 `.fullSizeContentView`，再按 `windowButtonVisibility` 隐藏或显示三个原生按钮；该方法不设置 `toolbarStyle` 或按钮 frame，也不创建 `NSToolbar`。Apple 说明 [`titlebarAppearsTransparent`](https://developer.apple.com/documentation/appkit/nswindow/titlebarappearstransparent) 只停止绘制标题栏背景，须配合全尺寸内容；[`.fullSizeContentView`](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/fullsizecontentview) 只对仍有标题栏的窗口生效，内容伸入标题栏时可用 `contentLayoutRect`/`contentLayoutGuide` 和 [`NSView.safeAreaInsets`](https://developer.apple.com/documentation/appkit/nsview/safeareainsets) 识别遮挡。插件的 hidden 并不提供自适应 38 px 顶栏，Flutter `SafeArea` 也不能直接推出横向交通灯避让。
- **工具栏样式、标题隐藏与底线各有职责**：[`NSWindow.toolbarStyle`](https://developer.apple.com/documentation/appkit/nswindow/toolbarstyle-swift.property) 决定已存在的工具栏相对标题栏如何布局；[`.unified`](https://developer.apple.com/documentation/appkit/nswindow/toolbarstyle-swift.enum/unified) 让工具栏与标题 inline，[`.unifiedCompact`](https://developer.apple.com/documentation/appkit/nswindow/toolbarstyle-swift.enum/unifiedcompact) 缩减边距。Apple [WWDC20](https://developer.apple.com/videos/play/wwdc2020/10104/?time=353) 称 unified 适用于多数窗口，compact 的控件和高度更小，适用于内容优先且工具栏项目不多的场景；这不是对自绘 38 px 高度的规定。[`NSWindow.TitleVisibility.hidden`](https://developer.apple.com/documentation/appkit/nswindow/titlevisibility-swift.enum/hidden) 会隐藏标题并使**已有工具栏**上移，不等于隐藏工具栏；[`NSToolbar.isVisible`](https://developer.apple.com/documentation/appkit/nstoolbar/isvisible) 则控制工具栏是否显示。旧 [`NSToolbar.showsBaselineSeparator`](https://developer.apple.com/documentation/appkit/nstoolbar/showsbaselineseparator) 仅控制工具栏与内容之间的整体底线，Apple 现标注已废弃（macOS 10.0–15.0），无法分别设置侧栏与工作区底线。
- **Apple 的全高侧栏与局部分隔线**：[WWDC20 的 Mail 示例](https://developer.apple.com/videos/play/wwdc2020/10104/?time=112) 以 `NSSplitViewController` 的 sidebar item 配合 `.fullSizeContentView` 实现全高侧栏；[12:49 起的分区演示](https://developer.apple.com/videos/play/wwdc2020/10104/?time=769) 用 [`NSTrackingSeparatorToolbarItem`](https://developer.apple.com/documentation/appkit/nstrackingseparatortoolbaritem/init(identifier:splitview:dividerindex:)) 跟踪 split view 的分隔线，[`.sidebarTrackingSeparator`](https://developer.apple.com/documentation/appkit/nstoolbaritem/identifier/sidebartrackingseparator) 是自动寻找侧栏分隔线的标准标识；此 item 之前的工具栏控件显示在侧栏上方。Apple [14:15–15:25](https://developer.apple.com/videos/play/wwdc2020/10104/?time=855) 指出滚动分区可出现自动阴影；需要指定线或无分隔符时，按区设置 [`NSSplitViewItem.titlebarSeparatorStyle`](https://developer.apple.com/documentation/appkit/nssplitviewitem/titlebarseparatorstyle) 为 `.line` / `.none`，同时窗口 [`titlebarSeparatorStyle`](https://developer.apple.com/documentation/appkit/nswindow/titlebarseparatorstyle) 保持 `.automatic` 才不覆盖子项。该 API 需要每个 item 对应自己的标题栏 section；Flutter 自绘 Row **不会自动成为** AppKit split view item。[`allowsFullHeightLayout`](https://developer.apple.com/documentation/appkit/nssplitviewitem/allowsfullheightlayout) 控制 sidebar item 的全高行为，不是移动交通灯的接口。

### 本项目的布局选择（尺寸并非 Apple 规定）

1. [顶栏](../../lib/ui/widgets/desktop_title_bar.dart) 的工作区标题从交通灯和侧栏开关右侧起步，允许跨过侧栏右缘；顶栏为标题限定宽度，把中间区域留给状态和快速打开。收起时也仍显示标题，并保持开关原位。展开态 248 px、收起态 56 px 的侧栏宽度不再限制标题长度。
2. macOS 顶栏不画贯穿顶部的侧栏分界纵线，改为一条横向底线，把顶栏与下方侧栏、工作内容区分开；Windows 仍使用原有的纵线和局部底线。它是 Flutter 自绘的效果，对应 Apple 按分区控制分隔线的视觉思路，并没有接入 AppKit `NSSplitViewItem.titlebarSeparatorStyle`。[Apple 分区样式](https://developer.apple.com/documentation/appkit/nssplitviewitem/titlebarseparatorstyle)
3. 原生 [MainFlutterWindow.swift](../../macos/Runner/MainFlutterWindow.swift) 让 AppKit 管理三个原生按钮的定位、悬停和点击；[app.dart](../../lib/app.dart) 的 80 px 仅作为 Flutter 顶栏避让宽度，不移动原生按钮。曾尝试为每个按钮手动增加位置约束，实机反馈圆内符号的悬停区域与按钮画面错位，因此撤销这项定制。当前在 [main.dart](../../lib/main.dart) 调用 `macos_window_utils` 的 `initialize()`、`addToolbar()` 和 `setToolbarStyle(.unifiedCompact)`，让 AppKit 自行调整按钮与命中区；[MainFlutterWindow.swift](../../macos/Runner/MainFlutterWindow.swift) 按该插件的 macOS 12 接入要求包装 Flutter 视图，并保留 `titlebarSeparatorStyle = .none` 避免与 Flutter 底线重叠；本机用 800×600 的原生临时窗口验证，未设工具栏时交通灯中心距顶 16 pt，设置后为 20 pt、内容布局上缘为 40 pt。Flutter 顶栏同样为 40 pt，Windows 仍保持原有高度。[Apple 标准按钮](https://developer.apple.com/documentation/appkit/nswindow/standardwindowbutton(_:)) · [插件源码](https://github.com/leanflutter/window_manager/blob/main/packages/window_manager/macos/window_manager/Sources/window_manager/WindowManager.swift#L379-L402)
