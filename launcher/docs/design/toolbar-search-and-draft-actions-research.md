# 工具栏搜索与草稿操作状态：一手规范摘录

调研日期：2026-09-25。范围：桌面/Web 工作台的重复搜索入口，以及 Undo / Redo / Discard / Save。以下“建议”是对 ct 的应用判断，不是设计系统的逐字规定。

## 官方依据

- **搜索范围与重复入口**：Carbon 按数据范围和所在位置安排搜索：全局搜索放全局 header，表内搜索放表格；当前页小数据集可用即时搜索，明确的 scope filter 可让一个搜索框跨范围检索。其即时搜索已有输入即反馈，不另放 Search / Go 按钮。Fluent 允许窄布局把搜索框收起成放大镜，再展开同一个搜索框。两份规范均未明文禁止两个搜索入口；“避免相同作用域重复出现”是据此作出的本项目判断。[[Carbon Search](https://carbondesignsystem.com/patterns/search-pattern/)] [[Fluent Searchbox](https://fluent2.microsoft.design/components/web/react/core/searchbox/usage)]
- **工具栏语义**：Fluent 将 toolbar 用于当前视图/任务的常用操作，要求关联操作分组，破坏性或影响工作状态的操作与其余操作隔开；图标动作须有可见用户可获知的文字提示与读屏名称。WAI-ARIA APG 建议一个工具栏占一个 Tab 停靠点，方向键在控件间移动；多个工具栏分别命名，若放文本输入，横向工具栏宜置于末尾，避免与方向键冲突。[[Fluent Toolbar](https://fluent2.microsoft.design/components/web/react/core/toolbar/usage)] [[WAI-ARIA Toolbar 源文](https://github.com/w3c/aria-practices/blob/main/content/patterns/toolbar/toolbar-pattern.html)]
- **禁用的含义与焦点**：Material 的 disabled 不可聚焦、按下、拖动，也没有 hover 状态；Carbon 把临时依赖/前置条件造成的不可用保持可见，影响主操作时可用行内警示解释如何恢复。APG 则允许为发现性关键的禁用 toolbar 控件保留焦点并标 `aria-disabled="true"`；一般可推断的禁用控件可跳过。保留焦点时仍须阻止实际动作。[[Material States](https://m3.material.io/foundations/interaction/states/applying-states)] [[Carbon Disabled states](https://carbondesignsystem.com/patterns/disabled-states/)] [[APG 键盘界面源文](https://github.com/w3c/aria-practices/blob/main/content/practices/keyboard-interface/keyboard-interface-practice.html)]
- **对比度的边界**：WCAG 1.4.3 对 inactive 控件文字免除 4.5:1 要求，1.4.11 对 inactive 控件非文字形状免除 3:1 要求；Material 和 Fluent 也明确说真正 disabled 不必满足正常控件对比度。这是最低合规例外，不能推成“应当淡到不可辨”。正常按钮和关键提示文字须满足适用的文字 4.5:1、重要图标/状态标志 3:1；`aria-disabled` 且仍可聚焦但不能激活的控件，虽属 inactive 例外，也应按可感知目标主动提高辨识度。[[WCAG 1.4.3 W3C 源文](https://github.com/w3c/wcag/blob/main/understanding/20/contrast-minimum.html)] [[WCAG 1.4.11 W3C 源文](https://w3c.github.io/wcag21/understanding/21/non-text-contrast.html)] [[Fluent Button](https://fluent2.microsoft.design/components/web/react/core/button/usage)]
- **禁用原因**：Fluent 建议禁用按钮的 tooltip 说明不可用事项、原因及如何解锁；Atlassian 明确反对在原生 disabled 按钮上放 tooltip，因为无法可靠触发焦点/悬停，也反对把必要信息藏进 tooltip，建议就地校验、辅助文字或行内消息。两者冲突时，把关键原因显示在草稿状态条或问题列表；tooltip 只做非必要补充，若用可聚焦的 `aria-disabled` 方案，则将原因关联为辅助描述。[[Fluent Button](https://fluent2.microsoft.design/components/web/react/core/button/usage)] [[Fluent Tooltip](https://fluent2.microsoft.design/components/web/react/core/tooltip/usage)] [[Atlassian Tooltip](https://atlassian.design/components/tooltip/usage/)] [[Atlassian Button](https://atlassian.design/components/button/usage/)] [[APG Button 源文](https://github.com/w3c/aria-practices/blob/main/content/patterns/button/button-pattern.html)]
- **命名与危险层级**：Atlassian 要求按钮以动作动词开头、尽可能指明对象，同一区域一个 primary；其 warning 适于可能丢失数据的确认，danger 专用于破坏且不可逆操作的最终确认。Carbon 的 danger modal 用于破坏/不可逆且重大数据损失，标题和按钮应对应后果；Fluent 要求 Save 明示提交变化并提供成功/错误反馈，常见 Cancel/Close 含义不能混淆。[[Atlassian Button](https://atlassian.design/components/button/usage/)] [[Atlassian Button examples](https://atlassian.design/components/button/examples)] [[Carbon Modal](https://carbondesignsystem.com/components/modal/usage/)] [[Fluent Button](https://fluent2.microsoft.design/components/web/react/core/button/usage)]

## 对 ct 的具体建议

1. **Quick Open 留一个稳定入口**：当前标题栏和草稿条均有同一个 Quick Open（见 `desktop_title_bar.dart` 与 `workbench_draft_bar.dart`）。保留标题栏入口与 Ctrl/Cmd+P；草稿条专注草稿状态和四个操作，移除其中重复的放大镜。资源列表自己的筛选若仅作用于列表则可以并存，明确标成“筛选资源”，Quick Open 标成“快速打开资源”，不要都叫“搜索”。窄布局将标题栏搜索收为图标，但打开同一操作。[[Carbon Search](https://carbondesignsystem.com/patterns/search-pattern/)] [[Fluent Searchbox](https://fluent2.microsoft.design/components/web/react/core/searchbox/usage)]
2. **明确四种动作的状态**：Undo 有已生效草稿步骤时启用；Redo 有可重做步骤时启用；Discard 有待丢弃的草稿命令时启用；Save 仅在候选已完成、净差异非零、无阻塞项且工作区/保存守卫允许时启用。禁用时保留固定位置和可辨的图标/名称；忙碌或计算中显示“正在计算变更…”“保存中…”，阻塞时在草稿条给出“有阻塞项，打开问题列表”等可行动的说明。当前 `workbench_repository.dart` 的 `canSave` 已包含主要候选/差异闸门，本条是展示建议，不要求改变业务条件。[[Carbon Disabled states](https://carbondesignsystem.com/patterns/disabled-states/)] [[Atlassian Button](https://atlassian.design/components/button/usage/)]
3. **按语义命名和分组**：图标按钮的读屏名称与文字按钮一致，用“撤销草稿步骤”“重做草稿步骤”“放弃全部草稿”“保存 Schema 变更”；视觉空间足够时可缩为“撤销”“重做”“放弃草稿”“保存变更”，并在状态或上下文指明对象。Undo/Redo 相邻，随后以间距/分隔线隔开放弃，Save 为该区域唯一 primary；不要用笼统“删除”指代只清草稿、不删 YAML 的动作。快捷键放补充提示与帮助，不作唯一可发现路径。[[Fluent Toolbar](https://fluent2.microsoft.design/components/web/react/core/toolbar/usage)] [[Atlassian Button](https://atlassian.design/components/button/usage/)] [[APG 键盘界面源文](https://github.com/w3c/aria-practices/blob/main/content/practices/keyboard-interface/keyboard-interface-practice.html)]
4. **危险操作有层级**：工具栏上的“放弃草稿”用次级/中性外观且远离 Save；点击后确认对话框写清“放弃全部未保存的 Schema 草稿步骤？已保存的 YAML 不受影响”，确认按钮写“放弃草稿”，取消按钮写“继续编辑”。丢弃全部未保存工作可能造成数据损失，确认层可用 warning；若确实不可恢复且损失重大，可在最终确认按钮使用 danger。红色不要在日常工具栏与 Save 争夺主操作层级。[[Fluent Toolbar](https://fluent2.microsoft.design/components/web/react/core/toolbar/usage)] [[Atlassian Button examples](https://atlassian.design/components/button/examples)] [[Carbon Modal](https://carbondesignsystem.com/components/modal/usage/)]
