## MODIFIED Requirements

### Requirement: 面板服务与工作区
面板 SHALL 由原生本地服务启动，不依赖 Python；浏览器打开后展示侧栏模块导航（导出 / 翻译 i18n / 表格管理 / 日志 / 历史）。工作区根目录名 SHALL 在 `<740px` 顶栏呈现，导出页内容呈现工作区身份，桌面宽度不设全局顶栏。工作区不可用或配置缺失时 SHALL 给出明确错误与修复指引，而不是空白页；存在未完成事务时 SHALL 在恢复前禁止加载半套资源。

#### Scenario: 启动并打开面板
- **WHEN** 策划启动原生面板服务并访问本地地址
- **THEN** 无需 Python 即可访问五个模块，导出页呈现工作区身份；窄屏（`<740px`）顶栏同时显示工作区根目录名

#### Scenario: 工作区缺失
- **WHEN** 工作区目录或 `config/global.yaml` 缺失
- **THEN** 面板显示明确的错误信息与修复指引，不崩溃、不显示空白页

#### Scenario: 工作区待恢复
- **WHEN** 工作区存在未完成发布材料
- **THEN** 面板展示恢复状态和入口，恢复成功后再刷新资源；恢复失败保留材料与错误

### Requirement: 导出操作
面板 SHALL 提供全部表 × 全语言导出，按 `解析校验 / JSON / Accessor / FBS / Bundle` 五步展示进度。默认导出 SHALL 允许有效增量缓存复用并保持完整校验覆盖；`forced=true` SHALL 绕过计算与生成缓存并强制写出选中产物。错误 SHALL 中止未提交导出并持续提示失败阶段、问题摘要及日志入口。

面板导出 SHALL NOT 自动部署；仅可恢复地发布本地产物并在成功后推进成功账本，未变内容在默认增量导出中保持 mtime。`GET /api/workspace` 的 `deploy.targets` SHALL 保持 `[]`，Web 不提供部署入口。任务 SHALL 属于服务，关闭或刷新页面不等于取消；显式取消及服务关闭遵守发布安全边界。

#### Scenario: 全量导出成功
- **WHEN** 策划点击“开始导出”且校验通过
- **THEN** 依次呈现五阶段，生成或复用全部表全部语言产物，显示表数与耗时，不出现 i18n、flatc 或 deploy 步骤

#### Scenario: 面板导出不部署
- **WHEN** 面板导出成功且配置启用了 Unity 部署
- **THEN** 只发布本地产物并提交成功账本，不写 Unity Assets；部署仍由独立 CLI 操作执行

#### Scenario: 校验失败中止
- **WHEN** 类型、主键或 ref 校验失败
- **THEN** 导出终结为失败且未提交产物与账本保持原状，错误持续可见并可定位日志

#### Scenario: 导出中关闭页面
- **WHEN** 导出进行中策划关闭页签或刷新页面
- **THEN** 服务继续持有任务，重新打开后可查询真实状态，不自动取消或再次启动

#### Scenario: 无变更增量与强制导出
- **WHEN** 无输入变更时先默认导出，再执行 forced 导出
- **THEN** 前者复用有效结果并保留未变产物 mtime，后者完整重建和写出；两者产物语义一致

### Requirement: 表格管理
面板 SHALL 提供资源列表、表名搜索、模板状态筛选与详情；Table、Record、Enum 的新增、编辑、删除 SHALL 进入可撤销草稿，遵守 Schema workspace-draft 与 workbench 规格。保存 SHALL 只修改实际变化的 YAML，不自动创建、重建或删除 Excel、manifest、翻译或导出产物。模板状态 SHALL 联动独立、显式的模板生成与保留数据重建操作。

#### Scenario: 新增表
- **WHEN** 用户在弹窗创建 Table 并保存合法草稿
- **THEN** 新 YAML 落盘且资源可见，Excel 缺失时显示缺失状态，由用户独立生成模板

#### Scenario: 编辑表并保存
- **WHEN** 用户修改字段并保存
- **THEN** 仅 YAML 更新，原 Excel 保持不变；需要更新模板时提供独立入口

#### Scenario: 模板漂移
- **WHEN** schema 在面板外或 YAML-only 保存后变化而模板未更新
- **THEN** 列表与详情标记漂移，并提供“重建模板（保留数据）”操作

#### Scenario: 删除表
- **WHEN** 用户确认删除资源并保存草稿
- **THEN** 仅删除目标 YAML，Excel 与产物保留；确认文案明确范围且仍被引用时禁止删除

### Requirement: 日志与历史
面板 SHALL 提供按模块（导出 / 校验 / i18n / 模板 / 系统）及级别筛选的日志页，以及最近五次成功交互式导出记录。升级 SHALL 兼容读取当前 Web 历史并与原生历史去重合并，保持配置 cache_dir 解析；导入 SHALL 幂等且保留旧源文件。历史写失败 SHALL 作为独立警告，不把成功业务提交改成失败或诱导重放。CLI 导出 SHALL 不追加面板历史。

#### Scenario: 日志按模块筛选
- **WHEN** 用户选择“校验”模块
- **THEN** 只显示对应模块日志，其余模块隐藏，刷新保持合理阅读位置

#### Scenario: 历史只保留最近五次
- **WHEN** 成功交互式导出累计超过五次
- **THEN** 历史只展示最近五次，服务重启后仍可查询

#### Scenario: 导入旧 Web 历史
- **WHEN** 工作区有合法 panel_history.json，用户重复启动原生面板
- **THEN** 旧记录正确映射状态与耗时，与 native 历史去重排序，不重复追加或重新引入已裁剪记录，旧文件保留

#### Scenario: 历史损坏或写入失败
- **WHEN** 旧历史无法识别或成功导出后写历史失败
- **THEN** 保留原材料并提示警告，导出成功状态与成功账本不因此回退
