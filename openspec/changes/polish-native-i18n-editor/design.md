## Context

当前原生翻译页由 `WorkbenchI18nView` 直接渲染 `DataTable`；译文单元格 `_EditableCell` 是单个 `TextField`，默认单行，`onSubmitted` 同时承担保存，Esc 只恢复当前单元格。`TranslationRepository` 目前只维护筛选、分页、entries 和 `editedKey`，没有独立的草稿生命周期。现有全局快捷键在 `WorkbenchShortcuts` 中明确只使用带修饰键的组合，并把 `Ctrl/Cmd+S` 保留给 Schema 草稿。

本变更只改 Flutter 客户端呈现和交互，继续复用 `i18n.query`、`i18n.save`、`i18n.status` 与 `i18n.sync`；不修改 Rust 协议或 i18n 文件格式。参见 `proposal.md` 的范围与动机。

## Goals / Non-Goals

**Goals:**

- 为多行译文提供稳定的专注编辑器和明确草稿生命周期。
- 让筛选/分页继续作为条目导航，而不把完整长文本压进固定表格单元格。
- 用 IME 安全的键盘语义保存、取消和编辑，不改变内核保存规则。
- 在 1440×900、1280×800、1024×700 及 100%/125%/150% 缩放下保持可编辑、可导航、无主操作遮挡。

**Non-Goals:**

- 不引入翻译记忆、术语库、机器翻译、批量编辑或新的搜索后端。
- 不改变 `i18n.save` 的 wire 参数、`confirmed` 语义、状态判定或导出回退规则。
- 不把所有行内编辑都改成显式保存；短文本行内编辑继续保留失焦保存。
- 第一版不实现“保存并跳下一条”；后续可通过偏好扩展。

## Decisions

### D1: 选中条目与草稿放在 `TranslationRepository`

仓库新增 `selectedKey`、`draftText`、`draftDirty` 与明确的选中/取消/保存方法，专注编辑器只绑定仓库状态。相比把草稿放在 `_WorkbenchI18nViewState`，这样切换布局、重建子组件或重排筛选时不会丢失草稿，也能让表格行与编辑器的选中高亮共用同一数据源。

备选：局部 `StatefulWidget` 持草稿。实现更少，但重布局或响应式切换会丢草稿，且与仓库的 `saveRow` 状态更新容易分叉。

### D2: 导航与编辑区采用响应式分栏

在翻译页局部使用 `LayoutBuilder`：

- 内容宽度充足时，左侧保留现有条目表/导航列，右侧显示专注编辑器；表格仍可内部横向滚动。
- 中等宽度时改为上下布局，导航表在上、编辑器在下或作为整宽区域。
- 可用宽度不足以同时保证两栏操作时，选中条目后进入全屏编辑回退；返回列表保留选中项与草稿。

布局断点按翻译页可用宽度判断，不直接复用窗口级侧栏折叠阈值，因为模块轨道和内容 padding 会改变可用空间。

### D3: 专注编辑器使用显式保存和本地草稿

专注编辑器使用 `TextField(maxLines: null)`、多行键盘类型、滚动容器和独立 `FocusNode`；`onChanged` 只更新草稿，不调用 `i18n.save`。保存按钮与 `Ctrl/Cmd+Enter` 调用同一个仓库方法，固定发送 `confirmed: true`，并只在成功后采用内核返回 status 更新条目。失败时保留草稿、焦点和选中项。

短文本行内编辑保留现有 `_EditableCell` 失焦保存路径，但不再负责长文本；两条路径必须最终都调用同一个 `saveRow` 语义，避免状态判定分叉。

备选：专注编辑器也失焦保存。对多行内容会造成滚动、点原文、切窗口时意外提交，且无法清晰展示未保存状态，因此不采用。

### D4: 键盘处理放在编辑器局部 `Focus` / `Shortcuts`

编辑器在 `TextField` 外层注册本地意图：

- `Enter` / `Shift+Enter`：保持多行控件的默认换行行为，不绑定提交。
- `Ctrl/Cmd+Enter`：调用保存并确认。
- `Esc`：恢复最近一次已保存文本并清除 dirty。
- `Ctrl/Cmd+S`：不注册，继续冒泡给 `WorkbenchShortcuts`。

处理键事件前检查 `TextEditingController.value.composing.isValid`；组合态直接 `ignored`，把事件留给输入法。这样既不占用单键，也不破坏已有全局快捷键和中文输入法候选流程。

### D5: 选中生命周期与筛选

`selectedKey` 只在当前结果集内有效。切换表/语言时清空选择和草稿；筛选或分页刷新后，如果选中键仍在 `entries` 中则保留，否则清空编辑器。保存成功后即使条目已不再匹配当前 active filter，当前编辑区仍显示该条目和内核返回的最新状态，直到用户主动切换或刷新；下一次查询由内核决定该条是否进入结果集。这样用户在 missing/stale 过滤下保存时不会突然丢失编辑上下文。

## Risks / Trade-offs

- [响应式两栏在 1024 宽度下可能过窄] → 用局部可用宽度做断点，窄窗改上下布局或全屏回退，并覆盖 1024×700 与 150% 缩放测试。
- [IME 与快捷键处理顺序存在平台差异] → 使用 `composing.isValid` 防护；测试组合态与组合结束后的保存路径；不把单键 Enter 绑定为保存。
- [两套保存路径可能出现状态不一致] → 两条路径都调用仓库单一 `saveRow`，并由 widget/state 测试验证请求数量、`confirmed` 参数与内核回包处理。
- [响应式重布局丢失草稿] → 草稿和选中状态放在仓库，布局切换只重建视图，不重建草稿。
- [筛选刷新清掉正在编辑的条目] → 仅在选中键不再存在时清空；保存成功后的当前条目保留到用户主动切换。

## Migration Plan

纯客户端交互变更，无数据迁移。发布后现有 i18n 文件、内核请求形状和导出行为不变；回滚只需恢复翻译页 UI 与翻译仓库的草稿状态代码，不涉及业务文件回滚。
