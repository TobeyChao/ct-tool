## Context

动机见 proposal.md。现有 `launcher/lib/theme.dart` 已定义深林绿、浅底、状态色与中英文字体 fallback；`services/panel_service.dart` 管理冻结 Python `ct panel` 子进程。Web 已有 Schema 草稿、翻译编辑、日志和导出工作流，不能把 launcher 三个页面当成功能全集。

当前工作树有用户未提交改动，实施时须以届时的现行能力及测试为基线，不覆盖其他工作。旧 web-panel 中保存自动改 Excel 的描述与 workspace-draft 和实际保存路径冲突，本设计采用后者；浏览器专有 CSS/inert/手机断点不机械迁移到桌面。

## Goals / Non-Goals

**Goals:** 原生客户端完成现有业务任务；保持视觉一致性、键盘可达性与高密度表格可读性；耗时业务不阻塞 UI；后端替换不改变草稿守卫。

**Non-Goals:** 不在 Dart 实现 Schema 规则、Excel 解析、依赖计算或文件事务；不新增 Excel 数据编辑器；不把 mock 样板作为真实导出交付；首发不承诺 Linux GUI、手机或自动更新服务。

## Decisions

### 1. 复用 launcher，建立完整工作台

保留 Flutter 平台工程、托盘/启动偏好与可复用基础控件，替换“启动面板”主流程。模块为工作区总览、Schema、翻译、导出任务、历史与设置。Schema 页采用资源区 + 主编辑器 + 属性区，底部任务区可折叠；资源和属性区支持拖动宽度、显式折叠及按工作区记忆。首屏优先展示主编辑器；窄窗口折叠辅助区，用户再手动展开。数据预览只读、按需分页。

选择 Flutter 重做展示层而非 WebView，是为了形成独立桌面体验；原网页仅作视觉与行为对照，不能直接复用 HTML/CSS。

### 2. 先做有质量门槛的样板

沿用现有浅色深林绿方向，抽取统一的颜色、字号、间距、圆角、边框、行高、焦点令牌；精简 Material 默认外观，不依赖装饰性动画。覆盖中英文长名称、长路径、错误、空态、忙碌、草稿冲突与进度状态。

首个里程碑交付可运行样板及 1440×900、1280×800、1024×700 逻辑尺寸截图。100%/125%/150% 系统缩放分别检查，无截断的主操作、重叠和页面级横向溢出；表格内部可横滚且表头对齐。界面样板约 3–5 人日，实际完整界面/打包约 4–7 人周，为初估而非交付承诺。完整任务仍须真实 worker 验收。

### 3. Dart 只持有展示状态和草稿日志

传输 client → 应用 controller → 视图模型 → widget 分层；传输接口可以接协议夹具或真实进程。候选由内核基于原始 schemaRevision + commands + cursor 计算，返回净差异和 candidateHash。刷新候选不能推进草稿基线。保存成功才替换基线；冲突时保留历史供显式重载/修正。

草稿存储在应用用户数据目录，按规范化工作区身份和基线隔离；启动恢复时先验证工作区和基线，不静默套用过期命令。旧浏览器 IndexedDB（ct-drafts）草稿不自动迁移；localStorage 仅为小型偏好，切换提示先在旧端保存；不扫描浏览器目录。

### 4. stdio worker 优先，协议由内核 change 拥有

消费 `../rust-native-core/design.md` 的协议 v1。worker 是应用私有子进程，不开 HTTP 端口；内核负责业务/持久化，Flutter 管理连接及任务展示。分页预览和批量事件避免大表穿过通道；stdout 只解析协议，stderr 作运行诊断。启动握手检查协议版本和能力，缺失能力显式禁用入口，不悄悄回退到 Python。

第一版不接 FFI：业务控制消息很小，进程边界便于隔离故障及复用 CLI；FFI 是否必要以后由测量决定。自动重连只重建连接和读取状态，不自动重放保存、模板、翻译或导出写请求。

### 5. 任务与桌面生命周期

一个工作区的写任务在内核互斥；不同任务事件按 requestId、workspaceId 隔离，切换工作区不混入旧结果。允许查看资源和滚动日志，冲突写入口显示占用原因。发布前支持取消；发布后展示“正在完成”，以内核终态为准。worker 断连且无终态则标记结果未知，不谎报取消或自动重试，重连后提示恢复状态。

关闭窗口默认可按既有偏好隐藏到托盘；显式退出遇到未保存草稿/运行任务提供保留草稿、等待或取消选项，取消受发布边界约束。正常退出发送 shutdown 并等待安全退出，不把 kill 当取消。

### 6. 已发现的迁移边界补充

现有功能覆盖见 `../rust-native-core/coverage.md`。Enum 值编辑、ordinal 风险、全局 Quick Open、引用跳转、YAML 差异、逐字段撤销、全局草稿条、帮助/关于/文档入口都属于迁移范围，不因浏览器展示层退役而删除。

候选请求使用单调 draftGeneration；只接纳匹配当前 workspace/baseline/cursor/generation 的响应。候选计算未完成或保存期间禁用提交；保存期间冻结草稿写操作，避免成功响应清掉后续编辑。保存成功但状态刷新失败仍显示保存成功。草稿持久化含 formatVersion、基线、完整 commands 和 cursor，采用原子写；磁盘满/权限失败保留内存编辑并持续警告。损坏或旧格式原文件保留供查看，不自动清空。

日志/任务由 Rust worker 提供 logs.list、tasks.list/issues/dismiss；历史由 Rust 在桌面成功导出后追加并通过 history.list 提供，兼容既有 panel_history.json 最近五次记录。Flutter 不直接扫描工作区目录、修改历史或推测业务统计；移除 StatsService 对 config/schemas、i18n、output/json 的硬编码读取，所有路径和概览来自内核配置解析。

显式保留应用单实例、开机自启和托盘常驻。主窗口从固定 720×460、不可调整改为可调整大小；默认 1280×800，最小 1024×700 逻辑尺寸，旧尺寸迁移时夹到新下限，避免继承旧 setResizable(false)。退出路径（窗口、Cmd+Q、托盘、系统退出）共用同一草稿/任务协调器。

### 7. 功能迁移边界

| 工作流 | Flutter 职责 | Rust 职责 |
|---|---|---|
| Schema | 资源/字段/索引编辑、undo/redo、差异和冲突展示 | 命令重放、校验、候选、受守卫保存 |
| Excel | 状态、预览、打开文件、显式模板按钮 | 读取、迁移预检、模板写入 |
| i18n | 表/语言/状态筛选、列显隐、行内/长文本编辑、进度 | 查询、保存条目、sync/compact |
| 导出 | 过滤、进度、错误定位、取消、最近五次记录 | 构建、发布、完成策略 |
| 部署 | 独立操作和结果展示 | 部署实现；桌面 export 默认不自动 deploy |

## Risks / Trade-offs

- [大字段表/日志导致 UI 卡顿] → 虚拟化、分页、事件合并和有界日志缓冲；profile/release 模式测量，不用 debug 帧率验收。
- [重写丢失隐含流程] → 对照当前模块页面、Schema 浏览器测试和规格建立迁移清单；每项对应原生验收。
- [跨平台字体差异] → 沿用系统中英文字体 fallback，Windows/macOS 真机逐项检查高 DPI 与中文输入法。
- [两个 change 接口漂移] → v1 契约和样例由内核维护，Dart 和 Rust 跑同一协议夹具；不各造一套 DTO。
- [进程崩溃误报结果] → 保留未知终态、草稿、恢复材料；不自动重放写操作。

## Migration Plan

1. 消费内核 change 产出的协议 v1 样例；完成样板和视觉评审，将截图与发现记录为实施证据。
2. 按模块接入 Rust 能力；未接入处明确显示不可用，禁止以 mock 验收业务。
3. Windows/macOS 无 Python/无仓库环境验证安装、完整业务链和关闭重启。
4. 两个 change 共同通过后把正式桌面包切到 Flutter + Rust；旧 Web 仅作对照，应用不再启动 Flask。
5. 回滚使用旧版本安装包；共享数据格式不变。先让持锁进程退出并完成恢复，不能让旧进程读取未完成新事务。旧浏览器草稿与原生草稿相互独立。
