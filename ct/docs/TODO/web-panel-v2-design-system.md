# ct Web Panel v2 设计系统与全局改版范围

> 日期：2026-08-31
> 状态：原型阶段，供新版 OpenSpec 使用
> 目标：Schema 模块与既有导出、翻译、日志、历史功能必须属于同一个产品，不出现两套视觉语言和交互规则。

## 1. 设计判断

ct 是给游戏策划和工具开发者长期使用的桌面数据工具。它不是营销网站，也不是通用后台模板。界面应当像一个可靠、可预测的专用工作台：

- 高信息密度，但不拥挤；
- 操作与副作用边界清晰；
- 错误必须可定位、可修复；
- 结构化数据、字段路径和运行日志优先使用等宽字体；
- 动效只表达状态切换和操作反馈；
- 不使用大面积卡片、装饰性渐变或多层 modal 制造层级。

设计参数：

- 差异度：5/10，保持工具感，同时避免通用管理后台外观；
- 动效：2/10，仅保留 hover、pressed、切换和轻量反馈；
- 信息密度：8/10，面向桌面和键鼠操作；
- 标志性交互：所有跨文件副作用先进入可审阅的 Change Plan。

## 2. 全局应用壳

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 品牌 / 当前工作区路径                             状态与全局操作        │
├──────┬──────────────────────────────────────────────────────────────────┤
│ 模块 │ 当前模块内容                                                     │
│ 导出 │                                                                  │
│ 翻译 │ Schema 模块：资源树 / 主编辑区 / 检查器                         │
│ 结构 │ 其他模块：模块工具栏 / 主内容                                    │
│ 日志 │                                                                  │
│ 历史 │                                                                  │
├──────┴──────────────────────────────────────────────────────────────────┤
│ 可选的任务状态、草稿或运行进度条                                       │
└─────────────────────────────────────────────────────────────────────────┘
```

全局规则：

1. 顶栏只承载品牌、工作区路径、工作区健康状态和当前模块的主操作。
2. 左侧窄模块栏替代旧的顶部页签，避免 Schema 内部页签与全局页签竞争层级。
3. 只有 Schema 模块使用资源树和右侧检查器。其他模块根据任务采用单栏或双栏，不能为了形式统一强行三栏。
4. 页面级导航使用 hash 路由，资源切换不影响 Workspace Draft。
5. modal 只用于短生命周期确认或选择；复杂编辑、进度和错误详情使用工作区页面、检查器或宽抽屉。

## 3. 视觉 token

### 3.0 配色决策

沿用现有 Web Panel 与 launcher 的森林绿识别，不采用新版初稿中的通用开发者蓝。旧方案的核心色已经具备三个优点：

- `#1B4332` 与 `#2F7A56` 已经跨 Web Panel 和 launcher 使用，具有连续的产品识别；
- 森林绿与 Excel、配置数据和“可验证的稳定工具”气质相符；
- 主色在白色背景上的对比度充足，适合长时间桌面使用。

调整重点不在换品牌色，而在修复旧方案的灰阶与状态色：旧 `ink-3: #8B948E` 在白色上的对比度约为 `3.12:1`，不适合作为 10-12px 帮助文字。新版将弱文本收深到 `#69756D`，对比度约为 `4.81:1`；warning 也从偏浅的 `#B7791F` 收深，避免小字号状态文字对比不足。

### 3.1 颜色

| Token | 值 | 用途 |
|---|---:|---|
| `canvas` | `#F5F6F4` | 应用背景，沿用旧版柔和冷灰绿 |
| `panel` | `#F7F9F6` | 导航、检查器背景 |
| `surface` | `#FFFFFF` | 主编辑表面 |
| `surface-soft` | `#F0F2EE` | 表头、hover、次级表面 |
| `ink` | `#1B241F` | 主文本 |
| `ink-muted` | `#5A645E` | 次级信息 |
| `ink-faint` | `#69756D` | 帮助文字，满足白底小字 AA 对比 |
| `line` | `#E1E6DD` | 普通边界 |
| `line-strong` | `#CBD2C6` | 输入框与强调边界 |
| `brand` | `#1B4332` | 品牌标识、深色主操作 |
| `accent` | `#2F7A56` | 选中、焦点、主操作、可导航类型 |
| `accent-soft` | `#D8F3DC` | 选中背景与成功弱底色 |
| `safe` | `#26725A` | 成功与安全变更 |
| `warn` | `#9B5C16` | 数据依赖与待确认风险 |
| `danger` | `#B23B3B` | 阻塞、错误、破坏性变更 |
| `nav` | `#142019` | 顶栏与模块栏，不使用纯黑 |

语义色仅用于真实状态，不作为装饰。森林绿是唯一交互强调色；蓝青可以用于 group 等数据分类徽标，但不能承担按钮或选中状态。

关键对比度（白色背景）：

| 组合 | 对比度 | 使用范围 |
|---|---:|---|
| `brand #1B4332 / white` | `11.08:1` | 品牌与深色文字 |
| `accent #2F7A56 / white` | `5.20:1` | 主按钮、链接、焦点 |
| `ink-muted #5A645E / white` | `6.14:1` | 次级正文 |
| `ink-faint #69756D / white` | `4.81:1` | 10-12px 帮助文字 |
| `warn #9B5C16 / white` | `5.34:1` | warning 文本 |
| `danger #B23B3B / white` | `5.86:1` | error 文本 |

使用规则：

- 主操作使用 `accent`，hover 使用 `#266544`；一个工作区只显示一个实心主按钮；
- 选中项使用 `accent-soft` 背景和 `accent` 左边线，不能只靠文字变绿；
- 可点击的类型名、字段路径和 API 名称使用 `accent`；普通数据值保持 `ink`；
- success 与 active 都属于绿色家族，必须同时通过文案、图标或位置表达含义，不能只靠颜色；
- warning 和 danger 使用独立的暖黄、红色弱背景，禁止用绿色表达“已确认风险”；
- 日志区可以使用深色 `#121A16`，但主编辑区不做整页深色模式，避免 Excel 和长表格阅读疲劳。

### 3.2 字体

- 界面文本：系统 sans，优先保证中文平台一致性和可读性；
- 数据文本：`SFMono-Regular / Cascadia Code / Roboto Mono / Consolas`；
- 等宽字体使用范围：表名、字段名、类型表达式、路径、时间、日志、生成 API；
- 不把长段帮助文案全部设成等宽字体。

### 3.3 尺寸

- 顶栏：48px；
- 模块栏：54-58px；
- Schema 左内容区：默认 242-248px，收起后只保留现有 56px 模块 Activity Bar；
- Schema 右属性区：默认 280-300px，收起后保留 40px 右 Activity Bar；
- 常规控件：32-34px；
- 紧凑行：40-44px；
- 圆角：5-8px，仅用于可交互控件和独立表面；
- 阴影只用于浮层、悬浮 changeset 和临时反馈。

### 3.4 自适应断点

ct launcher 的窗口最小尺寸是 `720 × 460`，Web Panel 必须至少覆盖这一尺寸，不能只按设计稿宽度实现。

| 宽度 | 布局策略 |
|---|---|
| `≥ 1360px` | 完整工作台：左右 Activity Bar 常驻，资源区与属性区可同时展开 |
| `960-1359px` | 单辅助区工作台：左右 Activity Bar 常驻，资源区与属性区最多展开一个 |
| `600-959px` | 页面栈：资源列表 → 主编辑区 → 属性页，模块栏仍位于左侧 |
| `< 600px` | 手机布局：同一页面栈；模块导航移到底部 |

响应式约束：

- 页面根节点禁止使用会导致全局横向滚动的固定 `min-width`；
- 左侧现有模块栏同时承担 Left Activity Bar；Schema 激活时再次点击 `SC` 只收起/恢复资源内容区，不生成第二条资源轨；
- 右侧永久保留 40px Right Activity Bar；属性内容区收起后，活动 Tab 仍是唯一且稳定的恢复入口；
- 左右内容区只有 `activeTool / null` 两态，不提供折叠后再隐藏 Activity Bar 的能力；
- 禁止为 pane 引入 `hidden + collapsed + overlay` 组合状态，禁止用 `translateX()` 把完整侧栏移出视口；
- Activity Tab 必须具有 `aria-label`、`aria-pressed`、tooltip 和键盘焦点态；点击活动 Tab 收起内容，再次点击恢复最近上下文；
- 左右内容区偏好、宽度与 `Tables/Records/Enums` 分组状态分别保存；响应式投影不覆盖宽屏偏好；
- 资源、当前页签、字段选择、导航历史和 Workspace Draft 独立于 pane 生命周期；断点变化只改变布局投影；
- 中屏不使用 Overlay 或 scrim；打开左内容区时收起右内容区，打开右内容区时收起左内容区；
- pane 只使用一条 180-200ms 的 `grid-template-columns` 轨道过渡；内容由 Activity Tab 边界裁切展开/收回，禁止整块面板位移穿过 Tab；
- 激活的 Activity Tab 与内容区共享表面色、相邻边界和选中指示线，视觉上组成同一个 Side Area；收起后恢复为独立 Tab；
- `prefers-reduced-motion` 下始终即时切换，并正确更新焦点与 `inert/aria-hidden`；
- `<960px` 不把资源树或检查器负位移隐藏在视口外，而是条件渲染为可返回的路由页面；隐藏页面必须 `hidden/inert`，不可获得焦点；
- 从窄屏放宽时，资源、字段、页签和草稿恢复为并排窗格；从宽屏收窄时保留用户正在操作的最深上下文；
- 字段表表头与每一行必须共享同一列模板和实际宽度；横向滚动时作为一个整体移动，不能出现表头铺满而内容行收缩；
- 资源切换必须原子更新资源名、元信息、页签计数、字段/枚举值内容和检查器上下文，禁止出现标题已切换但仍显示上一资源内容的混合状态；
- `<960px` 的字段结构列表改为两行紧凑分组，不强行保留桌面五列；查询索引、依赖矩阵和代码 diff 等需要跨行比较的内容继续在自身容器横向滚动；
- Change Plan 在窄窗口中改为单栏，迁移映射表只在自身区域横向滚动；
- 高度 `460px` 时主内容、资源树、检查器分别独立纵向滚动，底部主操作保持可见；
- OpenSpec 验收必须包含 `1600×900`、`1360×768`、`1280×720`、`960×640`、`720×460`、`390×844`，以及 `100% / 125% / 150%` 缩放测试。

## 4. 共享组件契约

所有模块必须使用同一套基础组件，不得分别复制 CSS：

| 组件 | 统一规则 |
|---|---|
| `AppShell` | 顶栏、模块栏、工作区状态、焦点顺序 |
| `WorkbenchSideArea` | 左右共享 `Activity Bar + activeTool + content pane` 契约；宽屏双开、中屏单辅助区、窄屏页面栈 |
| `ModuleHeader` | 模块标题、说明、主操作、状态摘要 |
| `CommandBar` | 搜索、筛选、次级动作；主操作固定在右侧 |
| `DataTable` | 表头、行高、选中、空态、错误行、键盘焦点 |
| `Inspector` | 右侧低频配置；label 在输入框上方；错误在输入框下方 |
| `StatusBadge` | success / warning / danger / neutral 四类语义 |
| `InlineIssue` | 错误原因、位置和修复入口，不只显示“操作失败” |
| `TaskBar` | 导出进度或 Workspace Draft；内容随模块变化，视觉位置一致 |
| `Dialog` | 只用于短确认；危险动作必须显示具体对象和后果 |
| `Toast` | 只反馈已完成的轻量动作，不承载需要用户处理的错误 |
| `EmptyState` | 解释为何为空并提供唯一下一步，不使用装饰插画 |

## 5. 各模块改版映射

### 5.1 导出

保留现有导出和取消逻辑，改成“任务运行页”：

- 顶部命令栏设置范围、语言和强制重建；
- 中央展示步骤列表、当前步骤、已处理表和错误；
- 底部 TaskBar 在切换模块后仍可看到运行状态；
- 失败项点击后打开日志详情，不再只显示一行错误文本；
- 导出完成后展示输出和部署目标，不使用泛化成功 modal。

### 5.2 翻译 i18n

保留当前表格编辑能力，统一成 DataTable：

- 左侧可选的表列表替代“选择表” modal；
- 顶部 CommandBar 放语言、状态和搜索；
- 右侧 Inspector 展示当前条目原文、译文、状态和确认历史；
- missing / stale / orphan 使用统一状态颜色；
- compact 是危险批量操作，进入影响清单后确认。

### 5.3 Schema

使用新版三栏工作台：

- 左侧资源树：Tables / Records / Enums 分组可展开；内容区收起后复用现有 `SC` Activity Tab 恢复；
- 中央字段或枚举值编辑；
- 右侧字段检查器；
- CodeName 和 group lookup 在“查询索引”中配置；
- 所有改动进入 Workspace Draft；
- 通过 Change Plan 原子应用。

### 5.4 日志

使用全宽日志查看器：

- CommandBar 提供模块、级别、关键字和 follow latest；
- 日志行统一使用等宽字体；
- issue 可从导出/Schema 审查反向定位到对应日志；
- 错误详情在右侧 Inspector 展开，避免每行无限增高。

### 5.5 历史

不再使用简单的五行列表：

- 按运行时间倒序展示导出记录；
- 每条记录可查看范围、耗时、结果、输出和部署目标；
- 支持从历史跳转到对应日志；
- 第一版仍保留最近 5 次的后端限制，不擅自扩大数据能力。

### 5.6 全局错误与工作区不可用

- 工作区不可加载时使用占据主内容区的阻塞页面；
- 可恢复错误放在与对象相邻的 InlineIssue；
- 异步任务失败通过 TaskBar 保留，不因切换模块而消失；
- 顶栏只显示健康摘要，不把完整错误塞入状态 pill。

## 6. 交互一致性

同一动作在全产品使用同一词汇：

| 意图 | 统一文案 |
|---|---|
| 开始导出 | `开始导出` |
| 停止正在运行的导出 | `取消导出` |
| 保存单条译文 | `保存译文` |
| 准备 Schema 变更 | `审查并应用` |
| 丢弃未应用 Schema 变更 | `放弃草稿` |
| 关闭只读查看 | `关闭` |
| 退出尚未保存的局部编辑 | `取消` |

按钮层级：

- 每个可见工作区最多一个 primary action；
- destructive action 永远不使用 primary 蓝色；
- 禁用按钮附近必须说明阻塞原因；
- 行操作默认收进上下文菜单，但高频动作可以直接显示。

## 7. 前端实现边界

当前前端是 Vue 3 全局脚本、无构建流程。统一改版不能继续把所有模板、状态和样式累加到单个 `app.js` / `index.html`。

OpenSpec 应至少要求：

1. CSS 拆分为 token、base、layout、component 和 module 层；
2. Vue 代码按全局 shell、导出、i18n、schema、日志、历史拆分；
3. 共享请求、错误、任务状态和焦点管理逻辑；
4. API 行为与现有 CLI 用例保持一致；
5. 在不引入前端构建链的前提下优先使用原生 ES module；若浏览器/打包约束不允许，再采用清晰的全局模块命名空间；
6. 不在前端序列化 YAML，所有 Schema 写入由后端负责；
7. 样式切换和组件重构必须有截图回归或至少关键状态的浏览器验收。

## 8. 实施顺序

1. 建立 token、共享组件和全局 AppShell；
2. 迁移导出、日志、历史，验证共享框架不会改变业务行为；
3. 迁移 i18n 数据表和批量操作；
4. 实现新的 Schema Workspace Draft 与 Change Plan；
5. 做跨模块错误、任务进度和键盘导航回归；
6. 移除旧页面样式和不再使用的 modal 逻辑。

Schema 不是单独换皮。新版 OpenSpec 必须把“全局 Web Panel 统一设计”列为显式交付范围，同时把 Schema 的领域模型和安全迁移作为其中最重的业务子系统。
