# 原生运行时升级与回滚

当前主入口为 Rust `ct` 的 CLI/Web 和内置运行时的 Flutter launcher。
macOS 是本轮支持与验收平台，Windows 延后，Linux 不支持；用户无需安装 Python。
G1/G2/G3、真实 Unity 联调与 Python 删除后的干净源码复验已通过。

## 升级

1. 正常停止旧面板并等待正在执行的导出结束，关闭旧虚拟环境的终端激活。
2. 在服务停止时备份整个工作区，包含配置自定义目录、Excel/manifest、翻译、产物、成功账本和 `.ct/`。
   若存在 journal，连同对应备份/暂存一起保留，不只备份 `config/`。
3. 安装原生 launcher 或解压 ZIP；终端以明确的 `bin/ct` 路径执行 `--version` 和 `status --root <工作区>`。
   用 `command -v ct` 核对 PATH 中旧 pip/venv 同名命令，不能仅凭程序名判断版本。
4. 有未完成发布时先用当前原生版本的 Web 恢复入口处理，再刷新工作区；损坏/未知 journal 或缺失备份
   会阻止写入并保留材料，需人工核对，不能删除 journal 后盲目继续。
5. 沿用原浏览器配置、协议、host 和端口，重新核对旧草稿与文件基线，再显式保存、更新模板或导出。

原生历史可导入旧 `panel_history.json`，原文件保留，重复启动不重复导入。
成功账本可接续，生成缓存不可信时丢弃重建。不要手改账本来消除待导出提示。

## 草稿与事务限制

IndexedDB 随 origin 隔离；把 `localhost` 换成 `127.0.0.1` 或更换端口不会自动搬迁草稿。
路径别名接续不能跨 origin。未知草稿格式和冲突基线保留查看，不能自动降级或重放。
浏览器请求丢失而任务结果待核实时，先核对任务/历史与产物，不能直接重复 POST 导出。

已知 `.ct/export-publication.json` 按原生恢复协议处理。旧 Apply journal、未知格式或缺备份
不会猜测恢复；请保留完整现场，具体规则见 [Schema 保存说明](schema-save-migration.md)。

## 原生版本回滚

回滚目标是已验收的原生版本，不使用 Python 回退。保留当前和目标版本的 ZIP/DMG、
`VERSION.json`、运行检查与产物格式约束。回滚前正常停止服务并备份完整工作区；
使用当前版本完成可识别的未结束事务，无法识别时不要换版本尝试写入。

替换运行时后先只读检查同一备份副本，再显式执行必要操作。若目标版本不能读取新 Schema、
缓存或 journal，恢复升级前的完整工作区备份与对应原生运行时；不要混合两次发布的文件。
原生版本相同格式也需要核对草稿基线，不承诺浏览器草稿自动向旧版本降级。

已用两个原生发行修订在自定义路径临时工作区演练完整备份/恢复、译文升级、旧原生版本重导出和未知 Apply 拒绝。
100 个备份文件内容与修改时间复核通过；该演练不保证任意未来格式自动向旧版本降级。
命令与 SHA 见 [退役验收记录](../native/docs/baseline/python-retirement-verification.md)。
